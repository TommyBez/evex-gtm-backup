## 1. Sintesi

La base tecnica è già solida e sopra la media per un sito nuovo: sitemap dinamica corretta, robots.txt con Content-Signal, canonical self-referenziali su tutte le pagine controllate, apex verso www in 308, 404 reali con `noindex`, contenuto interamente presente nell'HTML iniziale (verificato con curl, quindi nessuna dipendenza da rendering JS), JSON-LD ricco (Organization, WebSite con SearchAction, ItemList, SoftwareApplication, BreadcrumbList, TechArticle, Article, FAQPage, ProfilePage), llms.txt e llms-full.txt già serviti, mirror `.md` con `X-Robots-Tag: noindex`, TTFB 107 ms e Brotli. **Non ho trovato nessun blocco di indicizzazione.**

I tre problemi che pesano di più sono: (1) `createPageMetadata` passa `robots: undefined` e cancella silenziosamente le direttive robots/googlebot del root layout su 15 dei 28 URL, cioè su tutta la sezione contenuti (home, docs, learn, leaderboard); (2) la meta description delle pagine agente è la description grezza del registry, con backtick Markdown e lunghezze fino a 402 caratteri, quindi snippet SERP e card social sporchi; (3) le OG card di ogni agente mostrano `$ www.evex.sh/r/<slug>`, che non è il comando canonico `eve add https://www.evex.sh/r/<slug>.json` e non è nemmeno un comando eseguibile.

**P1-1. Direttive robots/googlebot azzerate su 15 URL su 28**

*Evidenza (codice)*: `apps/web/lib/metadata.ts:63-72`. Quando `noIndex` è `false` (default), la funzione ritorna comunque la chiave `robots` con valore `undefined`. Nel merge dei metadata di Next la chiave è presente nell'oggetto, quindi sovrascrive il `robots` definito nel root layout (`apps/web/app/layout.tsx:68-78`, che imposta `index, follow` più `max-image-preview:large`, `max-snippet:-1`, `max-video-preview:-1`).

*Evidenza (live)*: nessun `<meta name="robots">` né `<meta name="googlebot">` su `https://www.evex.sh/`, `/leaderboard`, `/docs`, `/docs/publishing`, `/learn`, `/learn/agent-registry`. Le stesse due meta sono invece presenti e corrette su `/agents/code-reviewer` e `/authors/TommyBez`, che non usano `createPageMetadata`.

*Pagine colpite* (tutte quelle che passano da `createPageMetadata`): home, `/leaderboard`, `/docs`, i 4 `/docs/*`, `/learn`, gli 8 `/learn/*`. Cioè esattamente le pagine di contenuto che dovrebbero puntare a snippet lunghi e anteprime immagine grandi.

*Impatto*: medio. Non toglie l'indicizzabilità (l'assenza di meta robots equivale a `index, follow`), ma annulla l'intenzione esplicita del root layout: niente `max-snippet:-1` sulle guide `/learn` e sui docs, niente `max-image-preview:large` per Discover e per le anteprime. È una regressione silenziosa: chi legge `layout.tsx` crede che le direttive siano attive ovunque.

*Fix*: in `apps/web/lib/metadata.ts`, costruire l'oggetto in modo condizionale e non includere affatto la chiave `robots` quando `noIndex` è falso.

```ts
return {
  title,
  description,
  alternates: { ... },
  openGraph: { ... },
  twitter: { ... },
  ...(noIndex
    ? { robots: { index: false, follow: false, googleBot: { index: false, follow: false } } }
    : {}),
}
```

Aggiungere un test che verifichi che `createPageMetadata({...})` senza `noIndex` non abbia la proprietà `robots` (`'robots' in result === false`).

*Effort*: S.

### P2

**P2-1. Meta description delle pagine agente: Markdown grezzo e fino a 402 caratteri**

*Evidenza (codice)*: `apps/web/app/(main)/agents/[slug]/page.tsx:76` usa `description: agent.description` così com'è, e lo stesso valore finisce in OG (`:93`), Twitter (`:109`) e nel JSON-LD `SoftwareApplication` (`apps/web/lib/structured-data.ts:115`). La description è Markdown per costruzione: `apps/web/components/agent-description.tsx` la renderizza con `ReactMarkdown` perché può contenere link e codice inline.

*Evidenza (live)*: su `https://www.evex.sh/agents/code-reviewer`, `<meta name="description">` contiene i backtick letterali: "Mention \`@code-reviewer\` on a pull request...", 239 caratteri.

*Evidenza (registry)*: lunghezze delle description in `/registry/*/registry.json`: programmatic-seo-agent 402, supabase-data-analyst 333, x-draft-assistant 332, x-hot-topic-digest 284, code-reviewer 239, postgres-data-analyst 175, openui-assistant 162. Sette pagine su undici superano i 160 caratteri.

*Impatto*: medio-alto sul CTR. Google tronca intorno ai 155-160 caratteri, quindi su 7 pagine su 11 lo snippet si interrompe a metà frase e non contiene mai il comando di installazione, che è la ragione per cui l'utente clicca. I backtick appaiono letteralmente in SERP e nelle card social.

*Fix*: aggiungere a `apps/web/lib/agent-detail.ts` un helper `getAgentMetaDescription(agent)` che (a) rimuove la sintassi Markdown inline (backtick, `**`, link `[testo](url)` ridotti a `testo`), (b) tronca sul confine di frase o parola a 155 caratteri, (c) se resta spazio, aggiunge la call to action con il comando canonico. Usarlo in `page.tsx` per `description`, OG e Twitter, e in `structured-data.ts` per il JSON-LD.

Esempio di copy risultante per `code-reviewer` (155 caratteri, nessun trattino lungo):

> Review GitHub pull requests from an eve agent: inline comments, suggestion blocks, and rate limiting. Install with eve add https://www.evex.sh/r/code-reviewer.json.

In alternativa, o in aggiunta, introdurre un campo opzionale `meta.docs.seoDescription` nello schema del registry, così ogni autore può scrivere la description SERP a mano; l'helper resta come fallback.

*Effort*: M (l'helper è S, ma va coperto con test e allineato allo schema del registry se si aggiunge il campo).

**P3-1. Gli endpoint `/r/*.json` sono crawlabili e indicizzabili**

*Evidenza (live)*: `https://www.evex.sh/r/code-reviewer.json` e `https://www.evex.sh/r/registry.json` rispondono `200 application/json` senza header `X-Robots-Tag`. `https://www.evex.sh/robots.txt` non contiene `Disallow: /r/`. Gli URL compaiono come testo nei blocchi di codice di `https://www.evex.sh/docs/registry` (`evex.sh/r/{slug}`, `evex.sh/r/registry.json`, `evex.sh/r/code-reviewer`).

*Evidenza (codice)*: `apps/web/app/r/[...name]/route.ts:51-55` imposta solo `Cache-Control: no-store`.

*Impatto*: basso. Sono 12 URL JSON su un sito di 28 pagine: se venissero indicizzati, sarebbero oltre il 30% di index bloat, e i JSON contengono il contenuto integrale dei file, quindi duplicherebbero il testo delle pagine agente.

*Fix*: aggiungere `'X-Robots-Tag': 'noindex'` alla risposta della route (non `Disallow` in robots.txt: con il solo disallow Google può comunque indicizzare l'URL senza contenuto). Nessun impatto sull'installazione: il CLI shadcn non legge robots.txt né X-Robots-Tag. Stesso trattamento già applicato correttamente ai mirror `.md`, che rispondono con `x-robots-tag: noindex`.

## 4. Cosa NON serve fare
